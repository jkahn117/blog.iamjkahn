# Repository instructions

Personal blog at <https://blog.iamjkahn.com>, built with Astro, React, Tailwind CSS, and Cloudflare Workers.

## Feature workflow

For each new feature:

1. Research the request and record findings in `_planning_/<feature>/research.md`. Research is complete when the document covers the current implementation, relevant constraints, and unresolved decisions.
2. Ask the user to review the research. Continue after they respond.
3. Write `_planning_/<feature>/plan.md` with checkable implementation and validation tasks.
4. Ask the user to review the plan. Start implementation after they approve it.

The `_planning_` directory is local workspace state and is ignored by Git.

## Project constraints

- Use the `@/` alias for imports from `src/`.
- Keep pages prerendered unless they require request-time behavior. The project uses server output so deferred components can run at request time.
- `src/components/Bluesky.astro` is request-time code. It reads Cloudflare environment bindings and caches the latest post. The index renders it with `server:defer`.
- Blog files use `YYYY-MM-DD-slug.md`. Build post URLs with `getPostSlug()` so the day stays out of the route.
- A post with `publish: false` stays out of public listings and routes. A post with `redirect_link` points listings and feeds to the external URL and has no local post page.
- `src/middleware.ts` owns legacy Blogger redirects. `/archive` redirects in `astro.config.ts`.
- `worker-configuration.d.ts` is generated by `wrangler types`. Regenerate it through `pnpm build`.

## Completion gate

For code or configuration changes, run:

1. `pnpm lint`
2. `pnpm format:check`
3. `pnpm build`

Oxfmt handles supported files. Prettier handles Astro templates.
